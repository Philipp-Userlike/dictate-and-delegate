# Build and test

Talk Router is an Android app (package `app.driftdictation`, kept from when it was called Drift, so updates install over it) (Java 17, Android SDK 36, AGP 8.13.2, Gradle 8.13). Set `JAVA_HOME` and the SDK path in a local `local.properties`. The Gradle wrapper is included; production has no external runtime dependencies.

```sh
./scripts/build.sh            # unit tests, lint, debug APK
./scripts/device-test.sh      # instrumented tests against a fake OpenRouter, a fake bb and a fake ntfy
```

UX checks by a persona agent on the emulator: [scripts/qa](../scripts/qa/README.md).

The debug APK is `app/build/outputs/apk/debug/app-debug.apk`. Android tests require a disposable Android 16 emulator: they replace the OpenRouter key and manipulate synthetic history, audio, permission grants, the clipboard and Quick Settings. Never run them on a phone with real Talk Router data. `device-test.sh` starts `scripts/fakes/fake_openrouter.py` on `DRIFT_TEST_PORT` (default 8797), forwards it with `adb reverse` and builds the app with `-PopenrouterUrl=http://127.0.0.1:8797/api/v1`. Tests save a fake key, queue transcripts, Jev answers (`decide`) and replies through the fake's `/test/script`, and read what the app sent from `/test/requests`. The fake reports fixed costs ($0.001 per transcription, $0.00002 per Jev decision, $0.0003 per text call). No provider calls, no charges. `scripts/fakes/fake_bb_mcp.py` stands in for bb's MCP server on the next port (`DRIFT_TEST_PORT + 1`, also forwarded): it answers `initialize`, `tools/list` and `tools/call` for `run`/`read`, recognises snippets by the bb command they call (`thread spawn`, `thread tell`, `thread show`), logs them at `/test/requests`, and takes queued failures at `/test/fail` and a required token at `/test/config`. `BbFlowTest` connects to it in custom-address mode. `scripts/fakes/fake_ntfy.py` (`DRIFT_TEST_PORT + 2`) serves a topic's JSON stream and polls, takes test publishes, and logs subscriptions. `PanelTest` drives the floating panel against `TestPadActivity` (a text field in the test APK): Insert and replace in place through the Accessibility service, the clipboard fallback, choices made while recording, the volume key (key events handed to `TalkAccessibility.onKeyEvent`; the emulator has no hardware volume key that reaches the accessibility filter), the chief's text back and ntfy's Copy broadcast. Pass `-e shots true` to save screenshots on the device under the app's `files/panel`. Tests read the clipboard only with Talk Router in front, since Android blocks clipboard reads from the background.

To sign a release, create `.signing/release.jks` with alias `drift`, put its password in `.signing/password`, then run `./scripts/release.sh 2.0.0 13` (version name and code). It writes a signed APK and an AAB to `dist/`. Both files are ignored.

Translations: UI text stays English in code as `tr("…")`. After adding or changing a text, run `scripts/i18n.py extract`, then `OPENROUTER_API_KEY=… scripts/i18n.py translate` to fill the seven other languages (it also drops texts the code no longer uses); `I18nTest` fails when one is missing. Review German by hand. Legal texts are `res/raw*/`.

Network: the app talks to OpenRouter (`OpenRouter`, base URL `BuildConfig.OPENROUTER_URL`, set with `-PopenrouterUrl=`; default `https://openrouter.ai/api/v1`), with the user's own key from `Vault`. Speech goes to `/audio/transcriptions` in chunks of about two minutes. Jev (`Jev`, `~typesafe/jev-latest`, 3 s timeout) goes to `/api/alpha/decisions` with up to three questions: `refine` and `template` (a choice over the template names), and `chief` only when the chief's name (`Profile.chiefName`) appears in the transcript (`Jev.mentions`: whole word, possessive, -y/-i/-ie variants); the question carries the name. Refine starts at 0.5 or a named template; the chief gets it at 0.8 and then Refine doesn't start by itself; 0.5–0.8, or Jev failing with the name present, only highlights 🧑‍💼. `scripts/qa/jev-check.py` asks the real Jev the same questions (read from `Jev.java`) on a labelled set and writes a report; it costs about $0.002 per run. Refine (`TextModel`, Claude Sonnet 5.5, 4,096 tokens, attachments as message parts, PDFs through OpenRouter's `file-parser` plugin) goes to `/chat/completions`. Each response's `usage.cost` is what the note and Activity show; a missing cost stays unknown.

bb: `BbBridge` talks to bb's MCP server (plugin `bb--mcp`) with `Mcp` (Streamable HTTP, protocol 2025-06-18, answers as JSON or event stream). Everything goes through the `run` tool, whose JavaScript snippet calls the bb CLI: `bb thread spawn --project proj_personal --title "Chief of staff" --prompt-file -` to create the chief (standing instructions in `BbBridge.chiefPrompt`), `bb thread show` to adopt an existing thread, and `bb thread tell <id> --mode queue --message-file -` to send (queued behind a running turn; on an idle thread it starts one right away). Text always goes as `stdin`, a JSON string literal, never spliced into argv or code. Snippets have 25 s and never wait. Two connection modes: bb Connect (`https://<handle>.getbb.app/mcp`, OAuth 2.1 with PKCE in `BbOAuth`; endpoints from the resource and authorization-server metadata, client ID = the URL of `oauth/client.json`, redirect `talkrouter://oauth/callback` handled by `BbSignInActivity`, refresh on expiry or 401, revoke on sign-out) or a custom address with an optional bearer token. Release builds allow plain HTTP only to 127.0.0.1/localhost (`res/xml/network_security_config.xml`) for `adb reverse`. The chief notifies through ntfy itself (`curl … -H "Click: <link base>/threads/$BB_THREAD_ID" <server>/<topic>`). Each message to the chief ends with `[request: <id>]`; text to paste goes back as an ntfy message tagged `talkrouter-paste` and `req-<id>`, with a broadcast action (`app.driftdictation.COPY_CHIEF_TEXT`, extra `request`) for ntfy's Copy button (`BbBridge.pasteCommand`). `ChiefText` reads the topic's JSON stream while the panel waits and fetches a request's text for the Copy broadcast, which `TalkAccessibility` receives. Thread links open with `Browser.EXTRA_APPLICATION_ID`, so Chromium browsers reuse one tab. Thread links are `<link base>/threads/<id>`, the link base being `https://<handle>.getbb.app` or what the user entered. The speech-model catalog is bundled in `assets/models.json`; `Profile.OFFERED` lists the models whose word hints work.

Debug-only hooks (absent in release because they check `BuildConfig.DEBUG`): launch extras `debugSeed` (sample notes) and `debugScreenshots` (lifts `FLAG_SECURE`). Debug builds also allow plain HTTP for the fake.

Main components: `DictationService` (capture, chunked transcription, the panel's session: Jev, Refine, the chief, Insert; recovery), `FloatingPanel` (the overlay: icon or buttons, wrapping to a second row when they don't fit), `TalkAccessibility` (volume key, Insert, replace in place, the Copy receiver), `Jev` (decisions), `ChiefText` (request IDs, the chief's text from ntfy), `AudioArchive` (retention), `HistoryStore` (encrypted versions/checkpoints), `TextModel` (the Refine call), `OpenRouter` (the HTTP client), `BbBridge` / `BbOAuth` / `BbSignInActivity` / `Mcp` (bb), `Attachments`, `Templates`, `I18n` (translations), `MainActivity` (UI), `DictationTile` / `OverlayIcon` / `RecordActivity` (starting).
